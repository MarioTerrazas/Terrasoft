### 2. Autenticación

Se implementó autenticación mediante JWT.

Endpoints funcionales:

- `POST /auth/login`
- `GET /auth/me`

Se utiliza:

- hash de contraseñas con Argon2 mediante `pwdlib`;
- tokens JWT mediante PyJWT;
- autenticación Bearer;
- expiración configurable desde `.env`.

El usuario administrador fue configurado con una contraseña cifrada.

### 3. Protección de rutas

Las rutas del sistema requieren autenticación.

Sin token:

- respuesta `401 Unauthorized`.

Con token válido:

- se permite el acceso según el rol del usuario.

### 4. Roles y permisos

Roles disponibles:

1. ADMINISTRADOR
2. VENDEDOR
3. ALMACENERO
4. CHOFER

Matriz inicial de permisos:

#### ADMINISTRADOR

- acceso completo;
- usuarios;
- clientes;
- productos;
- almacenes;
- inventario;
- movimientos;
- pedidos.

#### VENDEDOR

- administrar clientes;
- administrar productos;
- crear y consultar pedidos;
- consultar almacenes e inventario;
- no puede registrar movimientos de inventario;
- no puede administrar usuarios.

#### ALMACENERO

- consultar clientes y productos;
- administrar inventario;
- registrar movimientos;
- gestionar estados operativos de pedidos.

#### CHOFER

- consultar productos;
- consultar almacenes;
- consultar inventario;
- consultar pedidos;
- sin acceso administrativo.

Se confirmó que un vendedor recibe `403 Forbidden` al intentar realizar operaciones no autorizadas.

### 13. Ciclo de estados del pedido

Transiciones implementadas:

- PENDIENTE → CONFIRMADO;
- PENDIENTE → CANCELADO;
- CONFIRMADO → PREPARANDO;
- CONFIRMADO → ENTREGADO;
- CONFIRMADO → CANCELADO;
- PREPARANDO → ENTREGADO;
- PREPARANDO → CANCELADO.

Los estados finales son:

- ENTREGADO;
- CANCELADO.

No pueden volver a modificarse.

### 14. Reserva y descuento de stock

Comportamiento implementado:

#### PENDIENTE

No modifica inventario.

#### CONFIRMADO

Reserva la cantidad requerida.

Ejemplo probado:

- stock actual: 130;
- stock reservado: 2;
- stock disponible: 128.

#### PREPARANDO

Mantiene la reserva.

#### CANCELADO

Libera la reserva si el pedido estaba confirmado o en preparación.

#### ENTREGADO

- resta la cantidad del stock actual;
- libera la cantidad reservada;
- crea automáticamente un movimiento `SALIDA_VENTA`;
- registra al usuario autenticado que realizó la entrega.

## Decisiones de arquitectura

1. El stock actual no se modifica directamente mediante un CRUD.
2. Toda entrada o salida debe producir un movimiento.
3. La reserva se maneja separada del stock actual.
4. Los pedidos finalizados no se modifican.
5. Las operaciones críticas usan transacciones.
6. La reserva y entrega bloquean filas de inventario durante la operación.
7. Los precios se obtienen desde PostgreSQL.
8. El usuario responsable se obtiene del JWT.
9. Las eliminaciones principales son lógicas.
10. Las credenciales y claves permanecen fuera de Git mediante `.gitignore`.
